Mira Architecture

One n8n workflow with a router-pattern orchestrator and six agents on gpt-4o-mini. Code reads the project files, picks the agent and computes every count and date; each agent only writes up the facts it is given. Every request is traced in Langfuse. Clarifying questions stay in the chat; every other answer becomes a formatted Google Doc with PDF and Word download links, and a weekly workflow emails the status report as a PDF.

Why a router

PM requests vary: a plan, a risk list, a status count and a deadline check need different data and different prompts. A sequential pipeline would run every agent on every request, costing more and letting agents answer questions nobody asked. The orchestrator classifies once and one agent runs. The trade-off is that the router is a single point of failure, so its decision is visible in every Langfuse trace.

Code computes, the LLM writes

LLMs miscount rows and get date maths wrong. Route & Build Context counts tasks, applies the health rule, converts timeline weeks to dates and finds at-risk work before any agent runs. Agents are told to copy those facts exactly. Re-running a test changed the wording but never the facts.

Guardrails against fabrication

  • Vague or off-project requests go to the Clarifier, never to a generator.
  • Each agent only receives its own facts, so a Sprint 2 email cannot mention Sprint 3.
  • Rows are de-duplicated by ID, so a mis-set node cannot inflate counts.
  • Prompts forbid any task, risk, date or person not in the facts.
  • Documents are saved to the PM's own Drive, so they can be reviewed and edited before sharing.
  • Planned v2: a validator that checks every ID in the answer against the files.
